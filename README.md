# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:

- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

Важные файлы:

- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

## Установка и запуск

Перед запуском создайте в корне проекта файл `.env` со следующим содержимым:

```
VITE_API_ORIGIN=https://larek-api.nomoreparties.co
```

Переменная задаёт адрес сервера, к которому приложение обращается за данными о товарах и для оформления заказов.

Для установки и запуска проекта необходимо выполнить команды

```
npm install
npm run dev
```

или

```
yarn
yarn dev
```

## Сборка

```
npm run build
```

или

```
yarn build
```

# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

#### IProduct

Описывает товар в каталоге магазина. Используется везде, где приложение работает с товарами.

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

- `id` — уникальный идентификатор товара;
- `description` — описание товара;
- `image` — путь к изображению;
- `title` — название товара;
- `category` — категория товара;
- `price` — цена в синапсах. `null` означает, что товар «бесценен» и недоступен к покупке.

#### TPayment

Способ оплаты заказа. Может принимать одно из трёх значений: оплата картой онлайн, наличными при получении, либо пустая строка, если способ ещё не выбран.

```ts
type TPayment = 'card' | 'cash' | '';
```

#### IBuyer

Описывает данные покупателя, которые он вводит при оформлении заказа.

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

- `payment` — выбранный способ оплаты;
- `email` — электронная почта;
- `phone` — номер телефона;
- `address` — адрес доставки.

#### TBuyerErrors

Описывает объект с ошибками валидации данных покупателя. Каждое поле соответствует одноимённому полю `IBuyer` и необязательно: присутствует в объекте только если поле не прошло валидацию. Значение — текст ошибки.

```ts
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

Тип выводится автоматически из `IBuyer`: `keyof IBuyer` даёт набор имён полей, `Record<..., string>` строит объект с теми же ключами и строковыми значениями, а `Partial` делает все поля необязательными. При добавлении новых полей в `IBuyer` тип ошибок обновится автоматически.

#### IProductsList

Описывает объект, который возвращает сервер при запросе каталога товаров.

```ts
interface IProductsList {
  total: number;
  items: IProduct[];
}
```

- `total` — общее количество товаров;
- `items` — массив товаров.

#### IOrderRequest

Описывает объект, отправляемый на сервер при оформлении заказа. Расширяет `IBuyer`, добавляя итоговую сумму и список идентификаторов товаров.

```ts
interface IOrderRequest extends IBuyer {
  total: number;
  items: string[];
}
```

- `total` — итоговая сумма заказа;
- `items` — массив идентификаторов товаров, которые покупает пользователь.

#### IOrderResponse

Описывает объект, который возвращает сервер в ответ на оформление заказа.

```ts
interface IOrderResponse {
  id: string;
  total: number;
}
```

- `id` — идентификатор созданного заказа;
- `total` — списанная сумма.

### Модели данных

#### Products

Модель данных каталога товаров. Хранит массив всех товаров, полученных с сервера, и товар, выбранный для подробного отображения в модальном окне.

Конструктор не принимает параметров.

Поля:

- `items: IProduct[]` — массив всех товаров каталога;
- `selectedItem: IProduct | null` — товар, выбранный для подробного отображения.

Методы:

- `setItems(items: IProduct[]): void` — сохраняет переданный массив товаров в модель;
- `getItems(): IProduct[]` — возвращает массив всех товаров из модели;
- `getItemById(id: string): IProduct | undefined` — возвращает товар с указанным `id` или `undefined`, если такого товара нет;
- `setSelectedItem(item: IProduct): void` — сохраняет товар, выбранный для подробного отображения;
- `getSelectedItem(): IProduct | null` — возвращает выбранный товар или `null`, если ничего не выбрано.

#### Basket

Модель данных корзины. Хранит список товаров, которые покупатель выбрал для покупки, и предоставляет методы для управления этим списком и получения сводной информации.

Конструктор не принимает параметров.

Поля:

- `items: IProduct[]` — массив товаров, добавленных в корзину.

Методы:

- `getItems(): IProduct[]` — возвращает массив товаров, находящихся в корзине;
- `addItem(item: IProduct): void` — добавляет переданный товар в корзину;
- `removeItem(item: IProduct): void` — удаляет переданный товар из корзины по его `id`;
- `clear(): void` — очищает корзину;
- `getTotal(): number` — возвращает суммарную стоимость всех товаров в корзине;
- `getCount(): number` — возвращает количество товаров в корзине;
- `hasItem(id: string): boolean` — проверяет, есть ли в корзине товар с указанным `id`.

#### Buyer

Модель данных покупателя. Хранит данные, которые пользователь вводит при оформлении заказа (способ оплаты, адрес, email, телефон), и отвечает за их валидацию.

Конструктор не принимает параметров. Все поля инициализируются пустыми строками.

Поля:

- `payment: TPayment` — выбранный способ оплаты (`''` означает, что способ ещё не выбран);
- `address: string` — адрес доставки;
- `email: string` — электронная почта;
- `phone: string` — номер телефона.

Методы:

- `setData(data: Partial<IBuyer>): void` — сохраняет переданные данные в модель. Обновляются только те поля, которые присутствуют в `data`; остальные остаются без изменений;
- `getData(): IBuyer` — возвращает все данные покупателя одним объектом;
- `clear(): void` — очищает все поля покупателя (сбрасывает в пустые строки);
- `validate(): TBuyerErrors` — проверяет заполненность всех полей. Возвращает объект, в котором для каждого невалидного (пустого) поля указан текст ошибки. Если поле валидно — ключа в объекте нет. Если ошибок нет — возвращается пустой объект.

### Слой коммуникации

#### WebLarekApi

Класс, отвечающий за взаимодействие приложения с сервером. Использует композицию: в конструктор принимает экземпляр класса, реализующего интерфейс `IApi`, и делегирует ему выполнение HTTP-запросов. Знает конкретные эндпоинты API «Веб-ларька» и типы данных, которые сервер принимает и возвращает.

Конструктор:

- `api: IApi` — объект, через который выполняются HTTP-запросы.

Поля:

- `api: IApi` — сохранённый экземпляр API-клиента, используемый внутри методов класса.

Методы:

- `getProducts(): Promise<IProductsList>` — выполняет `GET`-запрос на эндпоинт `/product/` и возвращает объект с массивом товаров и их общим количеством;
- `orderProducts(order: IOrderRequest): Promise<IOrderResponse>` — выполняет `POST`-запрос на эндпоинт `/order/`, передавая данные заказа. Возвращает объект с идентификатором созданного заказа и списанной суммой.

### Слой представления (View)

Все классы представления наследуются от базового `Component<T>`. Они отвечают только за отображение данных и обработку действий пользователя: ловят DOM-события и уведомляют о них презентер через брокер событий или переданный в конструктор обработчик. Сами View не хранят бизнес-данные и не содержат логики приложения.

#### Card

Базовый класс карточки товара. Содержит общую для всех видов карточек разметку и сеттеры, используемые во всех наследниках.

Конструктор:

- `container: HTMLElement` — корневой элемент шаблона карточки;
- `events: IEvents` — брокер событий.

Поля:

- `_id: string` — идентификатор товара, который представляет карточка;
- `titleElement: HTMLElement` — DOM-элемент названия;
- `priceElement: HTMLElement` — DOM-элемент цены.

Методы:

- `setId(value: string): void` — сохраняет идентификатор товара;
- `getId(): string` — возвращает идентификатор товара;
- `setTitle(value: string): void` — записывает название в разметку;
- `setPrice(value: number | null): void` — записывает цену. Если `null`, выводит «Бесценно».

#### CardCatalog

Карточка товара в каталоге на главной странице. Используется шаблон `#card-catalog`.

Конструктор:

- `container: HTMLElement` — клон шаблона;
- `events: IEvents` — брокер событий.

В конструкторе на корневой элемент устанавливается слушатель `click`, генерирующий событие `card:select` с идентификатором товара.

Поля (дополнительно к `Card`):

- `imageElement: HTMLImageElement` — DOM-элемент изображения;
- `categoryElement: HTMLElement` — DOM-элемент категории.

Методы (дополнительно к `Card`):

- `setImage(src: string, alt?: string): void` — устанавливает изображение карточки;
- `setCategory(value: string): void` — устанавливает категорию и подменяет CSS-модификатор фона согласно `categoryMap` из `src/utils/constants.ts`.

#### CardPreview

Карточка для подробного просмотра товара в модальном окне. Используется шаблон `#card-preview`.

Конструктор:

- `container: HTMLElement` — клон шаблона;
- `events: IEvents` — брокер событий.

В конструкторе на кнопке покупки/удаления устанавливается слушатель `click`, генерирующий событие `card:buy` или `card:remove` в зависимости от текущего состояния.

Поля (дополнительно к `Card`):

- `imageElement: HTMLImageElement` — DOM-элемент изображения;
- `categoryElement: HTMLElement` — DOM-элемент категории;
- `descriptionElement: HTMLElement` — DOM-элемент описания;
- `buttonElement: HTMLButtonElement` — кнопка действия с товаром.

Методы (дополнительно к `Card`):

- `setImage(src: string, alt?: string): void` — устанавливает изображение;
- `setCategory(value: string): void` — устанавливает категорию и CSS-модификатор фона;
- `setDescription(value: string): void` — устанавливает текст описания;
- `setButton(state: 'buy' | 'remove' | 'unavailable'): void` — переключает состояние кнопки: «Купить», «Удалить из корзины» или заблокированная «Недоступно».

#### CardBasket

Карточка товара в списке корзины. Используется шаблон `#card-basket`.

Конструктор:

- `container: HTMLElement` — клон шаблона;
- `events: IEvents` — брокер событий.

В конструкторе на кнопке удаления устанавливается слушатель `click`, генерирующий событие `basket:remove` с идентификатором товара.

Поля (дополнительно к `Card`):

- `indexElement: HTMLElement` — DOM-элемент порядкового номера товара в корзине;
- `deleteButton: HTMLButtonElement` — кнопка удаления товара.

Методы (дополнительно к `Card`):

- `setIndex(value: number): void` — устанавливает порядковый номер позиции в списке.

#### Form

Базовый класс формы. Содержит общую логику для всех форм оформления заказа: отслеживание ввода, обработку отправки, отображение ошибок валидации и переключение активности кнопки отправки.

Конструктор:

- `container: HTMLFormElement` — клон шаблона формы;
- `events: IEvents` — брокер событий.

В конструкторе:

- на форме устанавливается слушатель события `input` — при изменении любого поля генерируется событие `form:input` с данными `{ field: string, value: string }`;
- на форме устанавливается слушатель события `submit` — отменяет стандартное поведение и генерирует событие `form:submit` с именем формы.

Поля:

- `form: HTMLFormElement` — корневой элемент формы;
- `submitButton: HTMLButtonElement` — кнопка отправки;
- `errorsElement: HTMLElement` — DOM-элемент для вывода ошибок валидации.

Методы:

- `setValid(isValid: boolean): void` — включает или отключает кнопку отправки;
- `setErrors(text: string): void` — выводит текст ошибки валидации;
- `clear(): void` — сбрасывает значения полей формы.

#### FormOrder

Форма первого шага оформления заказа: выбор способа оплаты и адрес доставки. Используется шаблон `#order`.

Конструктор:

- `container: HTMLFormElement` — клон шаблона;
- `events: IEvents` — брокер событий.

В конструкторе на каждую кнопку выбора оплаты устанавливается слушатель `click`. Клик имитирует событие `form:input` с `field: 'payment'` и `value: 'card' | 'cash'`.

Поля (дополнительно к `Form`):

- `paymentButtons: HTMLButtonElement[]` — кнопки выбора способа оплаты.

Методы (дополнительно к `Form`):

- `setPayment(value: TPayment): void` — выделяет активную кнопку оплаты модификатором `button_alt-active`.

#### FormContacts

Форма второго шага оформления заказа: email и телефон. Используется шаблон `#contacts`.

Не добавляет полей и методов сверх `Form` — отличается только используемым шаблоном.

#### Header

Шапка сайта. Содержит логотип и кнопку открытия корзины со счётчиком количества товаров.

Конструктор:

- `container: HTMLElement` — DOM-элемент шапки;
- `events: IEvents` — брокер событий.

В конструкторе на кнопке корзины устанавливается слушатель `click`, генерирующий событие `basket:open`.

Поля:

- `basketButton: HTMLButtonElement` — кнопка открытия корзины;
- `counterElement: HTMLElement` — DOM-элемент счётчика.

Методы:

- `setCounter(value: number): void` — обновляет число товаров в счётчике корзины.

#### Gallery

Контейнер каталога товаров на главной странице (`<main class="gallery">`).

Конструктор:

- `container: HTMLElement` — DOM-элемент галереи.

Поля:

- `container: HTMLElement` — корневой элемент галереи.

Методы:

- `setCatalog(items: HTMLElement[]): void` — заменяет содержимое галереи переданным массивом DOM-элементов карточек.

#### Modal

Универсальное модальное окно. Не знает о своём содержимом — отображает любую переданную в него DOM-разметку.

Конструктор:

- `container: HTMLElement` — корневой элемент модального окна;
- `events: IEvents` — брокер событий.

В конструкторе:

- на кнопке-крестике устанавливается слушатель `click`, закрывающий модальное окно;
- на корневом элементе устанавливается слушатель `click`, закрывающий модальное окно при клике вне его содержимого.

Поля:

- `content: HTMLElement` — контейнер, в который вставляется содержимое модального окна;
- `closeButton: HTMLButtonElement` — кнопка-крестик закрытия.

Методы:

- `setContent(node: HTMLElement): void` — заменяет содержимое модального окна переданным DOM-узлом;
- `open(): void` — открывает модальное окно (добавляет модификатор `modal_active`);
- `close(): void` — закрывает модальное окно (убирает модификатор `modal_active`).

#### Basket

Блок корзины (отображается внутри модального окна). Содержит список товаров, итоговую стоимость и кнопку оформления заказа.

Конструктор:

- `container: HTMLElement` — клон шаблона корзины;
- `events: IEvents` — брокер событий.

В конструкторе на кнопке «Оформить» устанавливается слушатель `click`, генерирующий событие `order:open`.

Поля:

- `listElement: HTMLElement` — контейнер списка товаров;
- `totalElement: HTMLElement` — DOM-элемент общей стоимости;
- `submitButton: HTMLButtonElement` — кнопка «Оформить».

Методы:

- `setItems(items: HTMLElement[]): void` — отображает переданные карточки товаров. Если массив пуст, выводит сообщение «Корзина пуста»;
- `setTotal(value: number): void` — устанавливает итоговую сумму корзины;
- `setValid(isValid: boolean): void` — включает или отключает кнопку оформления заказа.

#### Success

Экран успешного оформления заказа. Используется шаблон `#success`.

Конструктор:

- `container: HTMLElement` — клон шаблона;
- `events: IEvents` — брокер событий.

В конструкторе на кнопке закрытия устанавливается слушатель `click`, генерирующий событие `success:close`.

Поля:

- `descriptionElement: HTMLElement` — DOM-элемент описания со списанной суммой;
- `closeButton: HTMLButtonElement` — кнопка «За новыми покупками».

Методы:

- `setTotal(value: number): void` — выводит текст вида «Списано N синапсов».

### События приложения

Все события генерируются через брокер `EventEmitter` и обрабатываются в «Презентере» (`main.ts`).

#### События моделей данных

- `catalog:changed` — каталог товаров обновлён (например, после загрузки с сервера). Передаёт массив `IProduct[]`;
- `preview:changed` — изменился товар, выбранный для подробного просмотра. Передаёт `IProduct | null`;
- `basket:changed` — изменилось содержимое корзины (добавлен/удалён товар, корзина очищена). Передаёт массив `IProduct[]`;
- `buyer:changed` — изменились данные покупателя. Передаёт текущий объект `IBuyer`.

#### События представлений

- `card:select` — клик по карточке товара в каталоге. Передаёт `{ id: string }`;
- `card:button-click` — клик по кнопке покупки/удаления в карточке детального просмотра. Презентер сам определяет действие в зависимости от наличия товара в корзине. Передаёт `{ id: string }`;
- `basket:open` — клик по иконке корзины в шапке;
- `basket:remove` — клик по кнопке удаления товара из списка корзины. Передаёт `{ id: string }`;
- `order:open` — клик по кнопке «Оформить» в корзине;
- `form:input` — изменение значения в любом поле формы или выбор способа оплаты. Передаёт `{ field: string, value: string }`;
- `form:submit` — отправка формы. Передаёт `{ form: string }` (имя формы);
- `success:close` — клик по кнопке закрытия экрана успешного заказа.

### Презентер

Логика приложения реализована в файле `src/main.ts` без выделения в отдельный класс. Презентер выполняет три задачи:

1. **Создаёт экземпляры** всех моделей, представлений и брокера событий.
2. **Загружает каталог** с сервера через `WebLarekApi` и сохраняет в модель `Products`.
3. **Обрабатывает события** от моделей и представлений, связывая их между собой через методы моделей и сеттеры представлений. Сам не генерирует события.

Представления перерисовываются только в ответ на события моделей (`catalog:changed`, `basket:changed`, `buyer:changed`, `preview:changed`) или события открытия модальных окон.
